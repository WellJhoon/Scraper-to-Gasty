Fundamentos Técnicos

¿Cómo Scrapeamos Sin Credenciales de Usuario?

El secreto detrás de la extracción masiva de precios en los supermercados de RD.

💡 La Regla de Oro del E-Commerce Moderno
Para que una tienda online venda y aparezca en Google, los precios y productos DEBEN ser públicos para navegantes anónimos. Ningún supermercado exige login para ver cuánto cuesta la leche o el arroz. Este proyecto explota exactamente esas compuertas públicas.
Método 1 APIs Públicas de Storefront & BFF

En lugar de renderizar páginas HTML pesadas, las webs modernas usan SPAs (React, Vue, Angular) que consultan APIs REST o GraphQL públicas. El scraper emula directamente esas consultas JSON.

Usado en: La Sirena, Nacional, Jumbo, Plaza Lama, PriceSmart, Merca Jumbo, Garrido.
Método 2 Tokens Estáticos de Apps Móviles

Las aplicaciones nativas de iOS/Android no usan cookies de sesión web; suelen llevar tokens de API hardcodeados en el binario o User-Agents específicos de iOS (CFNetwork) que los servidores confían ciegamente.

Usado en: Bravo (iOS Domicilio App impersonation).
Método 3 Motores de Búsqueda Frontend Expuestos

Muchos sitios delegan su catálogo a motores ultrarrápidos (Typesense, Algolia). Las llaves de API "Search-Only" viajan en el JavaScript público del navegador. Se consulta al motor directamente, ignorando la web.

Usado en: Carrefour (Typesense QuickKart).
Método 4 Browser Automation Stealth (Bypass Cloudflare)

Cuando un supermercado coloca WAF agresivo (Cloudflare Turnstile / Challenges), un fetch simple recibe HTTP 403. Se levanta Puppeteer headless con fingerprinting de Chrome real y evasión de navigator.webdriver.

Usado en: Jumbo (para rescate de URLs y páginas protegidas).
Tip de navegación: Usa las teclas ◀ y ▶ de tu teclado para cambiar de diapositiva.

Detección Activa de Pantallas de Bloqueo Manejo Inteligente de Respuestas

El cliente inspecciona el título y contenido del HTML en tiempo de ejecución. Si detecta frases como:

"Just a moment..." "Attention Required! | Cloudflare" "Checking your browser" "503 backend read error"

El scraper espera activamente hasta 15 segundos a que el challenge de Cloudflare se resuelva solo, o categoriza el resultado como blocked / retryable sin marcar erróneamente el producto como "agotado" o "inexistente".

3

Catalog Sync & Árbol de Categorías

Supermercados Nacional (CCN)

Arquitectura Magento 2 Enterprise · REST API + Fallback HTML con Cheerio

¿Cómo se obtienen los datos?
Plataforma Base Magento 2 Open Source / Adobe Commerce
Endpoint Primario (REST API) /rest/V1/products?searchCriteria[filter_groups][0][filters][0][field]=sku
Fallback Secundario HTML Cheerio Selector: span[data-price-type="finalPrice"]
Mecanismo de Descubrimiento Sitemap XML oficial diff por SKU + lastmod
¿Qué salta y cómo evita credenciales?
1

Magento Guest Catalog Lookup

Por defecto, Magento 2 permite que la API /rest/V1/products responda consultas de productos para el storefront anónimo sin requerir Bearer Token.

2

Extracción Directa del SKU de la URL

Nacional genera URLs como /leche-entera-1-litro-102938. La expresión regular extrae el número final 102938 y consulta directamente a la API.

3

Verificación de Ofertas por Fecha

Valida special_price con special_from_date y special_to_date en el backend, evitando precios expirados.

La Estrategia Anti-Cloudflare

Jumbo bloquea con pantalla de desafío Cloudflare a bots básicos cuando buscan o navegan categorías.

A

Vía Rápida (80% del tiempo)

Para productos con SKU conocido, el scraper envía una query GraphQL limpia simulando un navegador Chrome con headers Origin y Referer.

B

Vía Stealth Browser (En recuperación de URLs)

Si la URL cambió o da 404, se lanza un navegador headless real con banderas de automatización eliminadas para buscar el producto como si fuera un usuario humano.

// Query GraphQL enviada a Jumbo (src/shops/jumbo.ts):
query JumboProductBySku($sku: String!) {
  products(filter: { sku: { eq: $sku } }) {
    items {
      sku name
      price_range {
        minimum_price {
          final_price { value }
          regular_price { value }
        }
      }
    }
  }
}

Plaza Lama

Motor Moira Engine · Apollo GraphQL con Client-Side DPL-API-Key

Ingeniería Inversa del Frontend
Plataforma Moira Engine (Digital Power Logistics - DPL)
Endpoint GraphQL PLAZA_LAMA_GRAPHQL_URL (Backend Cross-Site)
Llave de API Utilizada dpl-api-key (Extraída del JavaScript público de la web)
Referencia de Sucursal storeReference: "PL08-D" (Sucursal Churchill)
¿Cómo funciona sin login?

Plaza Lama utiliza una arquitectura desacoplada donde el navegador del cliente habla directamente con un backend Apollo GraphQL.

  • El frontend envía operationName: "GetProductsBySKU".
  • La cabecera dpl-api-key NO es una credencial privada del servidor; es un token de aplicación frontend embebido en los archivos compilados de la web.
  • El scraper reutiliza ese mismo token y envía el clientId: "PLAZA_LAMA".
  • Obtiene el precio base y las ofertas vigentes en promotion.conditions[0].price.
// Payload Apollo GraphQL (src/shops/plaza-lama.ts):
{
  "operationName": "GetProductsBySKU",
  "variables": {
    "getProductsBySKUInput": {
      "clientId": "PLAZA_LAMA",
      "skus": [sku],
      "storeReference": "PL08-D"
    }
  }
}

PriceSmart

Arquitectura Commercetools/BFF · Precios Multi-Club & Resolución de Pesaje

¿Cómo se obtienen los datos?
Endpoint de Producto PRICESMART_PRODUCT_API_URL (RPC Payload)

El Desafío Técnico: "Vendido por Peso"

En PriceSmart, carnes, pescados y quesos se venden por libra/kilo, pero el paquete final tiene un peso variable.

Detección de Categoría Regex sobre /carnes/, /cerdo/, /pollo/, /seafood/
Sold by Weight Validation sold_by_weight: true + validación con unit-utils.ts
Protección de Descuadre unitsAreClose() descarta si la unidad en DB difiere del empaque
Club Preference Ranking
Si el producto está disponible en varios clubes dominicanos con precios ligeramente distintos, el scraper usa un orden de preferencia predefinido: Los Próceres > San Isidro > Arroyo Hondo > Santiago.

La aplicación móvil oficial de Bravo para iPhone incluye un X-Auth-Token que utiliza el app para consultar el catálogo antes de que el usuario inicie sesión.

✓

¿Por qué no requiere credenciales de usuario?

En la arquitectura multi-tienda de Magento 2:

Magento no requiere un usuario logueado para mostrar precios mayoristas si la vista de tienda (store view) está configurada como accesible. Solo requiere enviar la cabecera Store: <código> en la consulta GraphQL.

2

Mapeo de SKUs de Nacional

Dado que Merca Jumbo comparte la base de datos de productos de CCN, los SKUs siguen el mismo formato y se extraen limpiamente de la URL.

Mecanismos de Resiliencia & Jobs Batch

Cómo el sistema previene baneos y se auto-repara cuando los supermercados cambian URLs.

Round-Robin Batches

En lugar de hacer 100 peticiones seguidas a Nacional y luego a Jumbo, el job scrape-prices-batch intercala un producto de cada súper por ronda, con delays aleatorios entre 600ms y 1200ms. Imposible de distinguir de tráfico orgánico.

Hidden Product Recovery

Si un supermercado cambia la URL (muy común en e-commerce), el scraper no pierde el producto. El job recover-hidden-products busca por SKU o código de barra y genera propuestas de recuperación para revisión administrativa.

Fix de Imágenes Rotas

Los CDNs de supermercados a menudo purgan fotos viejas. El job fix-broken-images-batch verifica si el enlace da 404 mediante peticiones HEAD y automáticamente extrae la nueva imagen vigente del producto.

Resumen Final
El proyecto logra una efectividad del 99%+ porque evita el scraping ciego de HTML siempre que es posible, prefiriendo APIs internas, tokens públicos de frontend, suplantación de clientes móviles y motores de búsqueda directos.
